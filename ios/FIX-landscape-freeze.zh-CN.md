# 横屏卡死修正（2026-11-06）

## 已确认的代码问题

此前 CameraView 的横屏、竖屏分别使用 if/else 分支，各自创建 CameraPreview。SwiftUI 切换分支时会销毁并重建 UIViewRepresentable，因而在旋转过程中把一个新的 AVCaptureVideoPreviewLayer 连接到正在运行的相机会话。

另外，PreviewHost.layoutSubviews 内直接设置 connection.videoRotationAngle，把相机连接变更放进了同步界面布局过程。截图不能证明具体内部锁或线程栈；本次针对这两处已发现的风险修改，仍需真机确认卡死是否消失。

## 本次修改

- 新增 CameraArrangement，用 AnyLayout 更换横竖布局算法，保持预览、设置区和快门的子视图身份，避免旋转触发预览销毁、重建和重新挂接。
- 预览角度不再在 layoutSubviews 内同步写入，改为在下一次主线程任务中更新；合并连续请求并读取最新窗口方向。
- 与实际当前连接角度比较；相机初始化、切换镜头后，即使设备方向没变，也可以对新连接重新应用方向。
- 只有实际改变角度后才重新排布构图线，避免更新循环。关闭预览时取消待执行操作，并解除会话挂接。
- UIKit 预览层操作继续位于主线程；相机启动、停止、配置与拍照仍在原相机队列，无同步跨队列等待。
- 拍照方向仍沿用按下快门时的设备方向；点击对焦与 RAW 显影流程保留。

## 验证范围

Windows 可执行的项目生成、参数/资源校验、Swift 语法解析和差异格式检查均不替代 Xcode 编译或真机运行。

新增 CameraLayoutTests.testRotationPreservesPreviewAndControlViews：在真实 UIHostingController 中反复切换生产布局，验证预览 UIView 与设置区 UIView 的身份不变、只创建一次且旋转时不拆除。测试不启动相机，不需要权限；它能验证预览生命周期，但不能验证真实 AVFoundation 连接的运行状态。本轮尚未执行该 XCTest。

真机安装新版后：

1. 竖屏 → 左横屏 → 竖屏 → 右横屏反复切换，检查取景持续刷新、设置可滑动、快门和关于按钮可点击。
2. 连续快速旋转后停下，检查画面方向和构图线是否正确、点击对焦是否仍准确。
3. 横屏切换镜头并拍 RAW，检查成片及相册方向，再切回竖屏拍摄。
4. 横屏进入后台再恢复，检查取景和按钮能继续操作。

如果仍卡死，需要该设备的挂起/线程日志进一步定位；不能仅凭截图声称已确定系统内部死锁原因。
